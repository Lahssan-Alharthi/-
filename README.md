# بوابة الموظفين — شركة مدد للخدمات اللوجستية

بوابة موظفين متكاملة باللغة العربية (RTL) تغطي دورة شؤون الموظفين كاملة إضافةً إلى العمليات
اللوجستية الخاصة بالشركة: الحضور، الإجازات، الرواتب، طلبات الخدمات، المستندات، الأسطول والرحلات،
التقارير، وسجل النشاط.

---

## التشغيل السريع

```bash
npm install          # تثبيت الاعتماديات
npm run seed         # تهيئة قاعدة البيانات ببيانات تجريبية
npm start            # تشغيل الخادم على http://localhost:3000
```

للتطوير مع إعادة التشغيل التلقائي: `npm run dev`
لإعادة بناء قاعدة البيانات من الصفر: `npm run reset`
لتشغيل الاختبارات: `npm test`

**المتطلبات:** Node.js إصدار 22.5 أو أحدث (يستخدم المشروع وحدة `node:sqlite` المدمجة).

## البنية التقنية

- **الخادم:** Node.js + Express
- **قاعدة البيانات:** SQLite عبر وحدة `node:sqlite` المدمجة في Node — بلا اعتماديات أصلية
- **الواجهة:** HTML/CSS/JavaScript بلا إطار عمل وبلا خطوة بناء، تطبيق صفحة واحدة بموجّه `hash`
- **المصادقة:** JWT في كوكي `HttpOnly`
- **تشفير كلمات المرور:** `scrypt` من `node:crypto` مع مقارنة ثابتة الزمن

## نموذج الصلاحيات

الصلاحيات معرّفة في `server/utils/rbac.js` بصيغة `المورد:الإجراء`، وتُفرَض على الخادم في كل مسار —
إخفاء عنصر في الواجهة ليس اعتماداً على الأمان. أبرز القواعد المطبّقة:

- الموظف يرى سجل حضوره ورحلاته وإشعارات راتبه فقط.
- المدير المباشر يعتمد إجازات فريقه فقط، ولا يعتمد إجازته الشخصية.
- بيانات الرواتب والحسابات البنكية محجوبة عمّن لا يملك `payroll` أو صلاحية الموارد البشرية.
- الموظف يعدّل حقولاً شخصية محددة فقط؛ أي محاولة لتعديل الراتب أو الدور تُتجاهَل على الخادم.
- إشعارات الرواتب لا تظهر للموظفين قبل اعتماد المسيّر.
- كل إجراء مؤثّر يُسجَّل في `audit_logs` مع المستخدم وعنوان الـ IP.

إضافات أمنية أخرى: تحديد محاولات الدخول الفاشلة، فحص أنواع الملفات المرفوعة وحجمها، ترويسات
`CSP` و`X-Frame-Options` و`nosniff`، واستعلامات مُعامَلة بالكامل ضد حقن SQL.

## متغيّرات البيئة

| المتغيّر | الافتراضي | الوصف |
|---|---|---|
| `PORT` | `3000` | منفذ الخادم |
| `HOST` | `0.0.0.0` | عنوان الاستماع |
| `NODE_ENV` | `development` | بيئة التشغيل |
| `JWT_SECRET` | قيمة تطوير | **إلزامي في الإنتاج** — يرفض الخادم الإقلاع بدونه |
| `DB_FILE` | `data/madad.db` | مسار قاعدة البيانات |
| `UPLOADS_DIR` | `data/uploads` | مجلد المرفقات |
| `MAX_UPLOAD_BYTES` | `8388608` | الحد الأقصى لحجم الملف المرفوع |
| `SEED_PASSWORD` | `Madad@2026` | كلمة مرور الحسابات التجريبية |

## ملاحظات قبل التشغيل في بيئة إنتاج

1. اضبط `JWT_SECRET` بقيمة عشوائية طويلة، وشغّل خلف HTTPS (الكوكي يصبح `secure` تلقائياً عند
   `NODE_ENV=production`).
2. البيانات التجريبية مخصّصة للعرض — استخدم `npm run reset` ثم أنشئ الحسابات الحقيقية، وغيّر
   كلمات المرور الافتراضية.
3. مجلد `data/` (قاعدة البيانات والمرفقات) خارج نطاق Git ويحتاج نسخاً احتياطياً منتظماً.
4. حسابات نسبة التأمينات الاجتماعية (9.75%) وطريقة خصم الغياب والسلف مبنية على إعدادات قابلة
   للتعديل في `server/config.js` — راجعها بما يوافق سياسة الشركة ولوائح المؤسسة العامة للتأمينات
   الاجتماعية قبل الاعتماد عليها في الصرف الفعلي.
